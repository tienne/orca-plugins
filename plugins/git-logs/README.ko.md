# Git Logs

[English](README.md) · 한국어

Git 로그, 트리, 커밋 그래프로 이력을 살펴보고 파일을 읽기 전용 좌우 Diff로 비교하는 Orca 플러그인입니다. 커밋 우클릭 메뉴에서 Git 변경 작업도 실행할 수 있습니다.

Git Logs 0.1.1은 Orca 1.4.248 이상과 로컬 Git이 필요합니다.

## 설치

1. Orca의 **설정 → 플러그인 → ⋯ → Catalog sources…**를 엽니다.
2. Git URL에 `https://github.com/tienne/orca-plugins.git`, ref에 `release`를 입력해 카탈로그를 추가합니다.
3. **Git Logs** (`tienne.git-logs`)를 설치하고 요청한 실행 권한을 확인합니다.

플러그인은 로컬 Git과 파일을 읽고, 비교 문서와 로컬 제외 규칙을 기록합니다. 확인한 Git 변경 명령도 실행할 수 있습니다. Node 워커는 사용자 계정 권한으로 동작하며 `workspace:read`, `workspace:write`를 요청합니다. 설치에 Node.js나 pnpm은 필요하지 않습니다.

## Git Logs 사용하기

1. Orca에서 로컬 Git 작업 공간을 열고 Git Logs 사이드바를 여십시오.
2. 현재 작업 공간에 자동으로 연결합니다. 작업 공간을 하나로 식별할 수 없으면 목록에서 선택하십시오.
3. 커밋을 선택해 메시지 전문과 변경 파일을 확인하십시오.
4. 파일을 **더블클릭**하거나 포커스를 두고 **Enter**를 누르면 중앙 Diff 탭이 열립니다. 한 번 클릭하면 파일만 선택합니다.

그래프는 최근 최대 200개 커밋의 부모 관계, HEAD, 브랜치, 작성자, 날짜, 해시를 보여 줍니다. 브랜치 선택창에서 현재 브랜치, 전체 브랜치, 특정 로컬 또는 원격 브랜치를 고를 수 있습니다. 이 선택은 이력 필터만 바꾸며 체크아웃하지 않습니다.

커밋 메시지, 작성자, 해시를 검색할 수 있습니다. 검색 범위는 불러온 이력입니다. 검색으로 빠진 커밋을 잘못 연결하지 않도록 검색 중에는 그래프 선을 숨깁니다. 브랜치는 별도로 조회해 최대 100개 검색 결과를 보여 주고 원격 HEAD 별칭은 제외합니다. 결과가 많으면 검색어를 더 입력하십시오.

**새로고침**을 누르면 Git 데이터를 다시 읽습니다. Orca 작업 공간을 바꾸면 연결이 바뀌고 브랜치 필터도 초기화됩니다. 새로고침할 때는 선택한 브랜치를 유지하지만 해당 ref가 삭제됐다면 현재 브랜치로 돌아갑니다.

## 파일 비교하기

| 선택      | 왼쪽                           | 오른쪽               |
| --------- | ------------------------------ | -------------------- |
| 작업 트리 | HEAD의 파일                    | 디스크에 저장된 파일 |
| 커밋      | 선택한 커밋의 부모에 있는 파일 | 선택한 커밋의 파일   |
| 최초 커밋 | 빈 트리                        | 최초 커밋의 파일     |

Merge 커밋은 기본적으로 첫 번째 부모와 비교합니다. 다른 직접 부모를 선택해 비교 기준을 바꿀 수 있습니다.

작업 트리의 상태 표시는 변경이 있는 위치를 뜻합니다.

- `staged`: HEAD와 Git index가 다릅니다.
- `unstaged`: index와 디스크의 파일이 다릅니다.
- `untracked`: index에 등록되지 않은 파일입니다. Git에서 무시한 파일은 제외합니다.

별도의 staged/unstaged Diff 모드는 아닙니다. **작업 트리 Diff는 HEAD와 디스크에 저장된 최종 내용을 비교합니다.** 변경이 상쇄돼 HEAD와 같아진 파일은 제외합니다. 편집기에서 아직 저장하지 않은 내용은 포함하지 않습니다.

뷰어는 좌우 코드를 정렬하고 줄과 단어 단위로 변경을 강조합니다. 동기 스크롤, 이전/다음 변경 이동, 변경 없는 영역 접기, 줄 앞뒤 공백 무시를 지원합니다. 좁은 화면에서도 좌우 비교를 유지하고 코드 안에서 가로로 스크롤합니다. 추가, 삭제, 이름 변경, 빈 파일, 없는 파일을 구분합니다. 텍스트로 비교할 수 없는 파일은 Diff 대신 상태를 표시합니다.

## 커밋 작업 실행하기

커밋을 **우클릭**하거나 포커스를 두고 **Shift+F10**을 누르십시오.

| 작업        | 결과                                                      |
| ----------- | --------------------------------------------------------- |
| 체크아웃    | 선택 커밋의 로컬 브랜치로 전환하거나 Detached HEAD로 이동 |
| 브랜치 생성 | 선택 커밋에서 로컬 브랜치 생성. 자동 전환하지 않음        |
| 병합        | 선택 커밋을 현재 브랜치에 병합                            |
| 리베이스    | 현재 브랜치의 커밋을 선택 커밋 위에 다시 적용             |
| 체리픽      | 선택 커밋을 현재 브랜치에 적용                            |
| 리버트      | 선택 커밋의 변경을 취소하는 새 커밋 생성                  |
| 리셋        | soft, mixed, hard 방식으로 HEAD를 선택 커밋으로 이동      |

옵션을 고른 뒤 저장소 상태를 검사하고 현재 브랜치와 대상을 확인해 실행하십시오. 변경 명령은 index와 작업 트리가 깨끗하고 untracked 파일이 없을 때만 실행됩니다. 지원하지 않는 상태나 이미 진행 중인 Git 작업이 있으면 거절합니다.

- Hard reset은 대상의 짧은 해시를 직접 입력해야 합니다.
- Reset과 rebase 전에는 HEAD를 `refs/git-logs/backups/<timestamp>-<uuid>`에 보관합니다. **커밋만 보존하며 미커밋 파일을 백업하지 않습니다.** 백업 ref는 자동 삭제하지 않습니다.
- Merge 커밋의 체리픽과 리버트는 기준 부모(mainline)를 선택해야 합니다.
- Rebase는 merge 커밋을 보존하거나 다른 브랜치 ref를 갱신하지 않습니다. Interactive rebase와 squash도 지원하지 않습니다.
- 다른 worktree에서 체크아웃한 브랜치를 강제로 가져오지 않습니다.
- 충돌이나 실패가 나면 Git 출력과 충돌 파일을 보여 줍니다. 터미널에서 해결하거나 계속 또는 중단하십시오. 자동 롤백이나 재시도는 하지 않습니다.

이 UI에서 실행하는 작업은 Git hooks와 커밋 서명을 비활성화합니다. 자동 stash, rerere 적용, submodule 재귀 갱신도 끕니다. 저장소의 filters와 merge driver는 실행될 수 있습니다. 작업 중에는 같은 저장소에서 다른 Git 명령을 실행하지 마십시오. 명령은 120초 후 중단되므로 중간에 멈췄다면 저장소 상태를 확인하십시오.

Staging, 일반 커밋 작성, fetch, push, force push, 자동 stash UI는 없습니다.

## 테마와 언어

패널, 메뉴, 확인창, Diff에 Orca가 공개한 테마 색상을 사용합니다. 한국어와 영어는 Orca 언어 설정을 따르고 다른 언어는 영어로 표시합니다. 커밋 메시지, 작성자, 브랜치 이름, 경로, 원본 Git 출력은 번역하지 않습니다. Monaco의 일부 내장 문구는 영어로 남아 있습니다. Orca 언어 변경이 반영되지 않으면 패널이나 탭을 다시 여십시오.

가운데 짧은 핸들을 드래그해 커밋 정보와 파일 목록 높이를 조절할 수 있습니다. 방향키, Shift+방향키, Home/End도 지원합니다. 핸들을 더블클릭하면 기본 높이로 돌아갑니다. 각 영역은 내부에서 스크롤합니다. 높이는 프레임의 로컬 저장소에 저장하고 저장소 접근이 제한되면 현재 프레임 안에서만 유지합니다.

## 접근 권한과 생성 파일

Git Logs는 `trusted-worker` 플러그인입니다. **Node 프로세스는 사용자 계정 권한으로 Git과 파일을 포함한 컴퓨터 자원에 접근합니다.** 실행 전에 승인이 필요합니다. `workspace:read`로 현재 작업 공간을 확인하고 `workspace:write`로 작업 공간과 Diff 탭을 엽니다.

Diff 탭을 열면 워크트리 안에 `.orca/git-logs/*.orcadiff` JSON 문서를 만들고 저장소·비교 기준·선택 파일을 기록합니다. 워크트리 폴더를 실제로 삭제하면 문서도 함께 삭제됩니다. 탭을 닫거나 Orca의 폴더 등록만 해제할 때는 문서를 삭제하지 않습니다.

워크트리 생성, 현재 작업 공간 전환, 사이드바 연결, 비교 로드, Diff 탭 열기에서 로컬 제외 설정을 확인합니다. Git으로 찾은 기존 `info/exclude` 파일에 `/.orca/git-logs/` 규칙이 없을 때 한 번 추가합니다. 기존 규칙은 보존하며 버전관리되는 `.gitignore`, index, 전역 Git 설정은 바꾸지 않습니다. 같은 로컬 저장소의 연결된 worktree들은 규칙을 공유하고 다른 clone에는 영향을 주지 않습니다. 이미 추적 중인 문서를 자동으로 추적 해제하지 않으며, 이전 `.orca/git-tools/` 경로도 이 규칙의 대상이 아닙니다.

로컬 제외 설정에 실패해도 비교 문서를 생성하고 Diff를 열며 경고를 표시합니다. 이 문서는 untracked 파일로 표시될 수 있고, 깨끗한 작업 상태를 요구하는 Git 동작을 막을 수 있습니다. Git 메타데이터가 없거나 안전하게 열 수 없는 경우, 쓰기 권한 부족, 우선순위가 높은 unignore 규칙은 로컬에서 해결해야 합니다. 플러그인은 없는 메타데이터를 만들거나 공유 규칙을 덮어쓰지 않습니다. Worker가 `workspace.created`, `workspace.changed`를 구독하므로 Orca가 구독 승인을 요구할 수 있습니다.

외부 `.orcadiff` 문서를 열어도 해당 저장소를 자동으로 신뢰하지 않습니다. Git Logs 사이드바에서 그 저장소에 연결한 뒤 문서를 새로고침하십시오. Diff 탭은 현재 작업 공간을 바꿔도 문서에 기록된 저장소와 비교 기준을 유지합니다.

UI, Monaco, SVG 아이콘, editor worker는 모두 로컬 번들에 포함됩니다. Telemetry, analytics, 외부 번역 서비스는 사용하지 않습니다.

## 지원 범위

- Orca가 관리하는 로컬 Git 작업 공간만 지원합니다. SSH나 임의 경로 연결은 없습니다.
- 원격 브랜치는 로컬에 저장된 ref만 읽습니다. Fetch나 Git LFS 다운로드는 하지 않습니다.
- UTF-8 텍스트 비교는 **파일당 768 KiB**, **변경 파일 2,000개**까지 지원합니다.
- 바이너리, 비 UTF-8, 큰 파일, symlink, submodule, 미해결 충돌은 별도 상태로 표시합니다.
- Shallow 저장소는 로컬 이력만 표시합니다. Partial clone은 자동 객체 다운로드를 피하기 위해 거절합니다.
- Git 데이터는 모두 같은 시점에 조회되지 않습니다. 다른 앱에서 변경한 뒤에는 새로고침하십시오. HEAD가 바뀌면 다시 불러와야 할 수 있습니다.
- 커밋 작업은 assume-unchanged, skip-worktree, sparse checkout과 진행 중인 merge, rebase, cherry-pick, revert, bisect 상태를 거절합니다. Ignored 파일이 대상 경로를 막아도 거절합니다.

`local.git-logs` 개발 빌드를 승인하고 macOS의 Orca 1.4.248에서 저장소 자동 연결, Diff 탭 두 개, Monaco 렌더링, 생성 문서의 로컬 Git 제외를 확인했습니다. 이름 변경 전 플러그인으로는 라이트·다크 테마도 확인했습니다. Git 변경 명령은 임시 저장소에서 검증했습니다. 다른 OS와 Orca 버전은 검증하지 않았습니다.

## 로컬에서 설치하기

Node.js 22.12 이상 또는 24 이상, pnpm 10, Git, Orca CLI를 준비하고 모노레포 루트에서 실행하십시오.

```sh
pnpm install
pnpm nx run git-logs:build
pnpm nx run git-logs:typecheck
pnpm nx run git-logs:test
pnpm nx run git-logs:ui-test
pnpm validate
```

설치용 빌드는 `dist/plugins/git-logs`입니다. 접근 범위를 검토한 뒤 개발 폴더를 연결하십시오.

```sh
orca plugin inspect ./dist/plugins/git-logs --json
orca plugin dev load ./dist/plugins/git-logs --json
```

Orca가 `approval_required`를 반환하면 요청한 권한을 읽고 Orca의 승인 절차를 따르십시오. 승인한 개발 폴더는 이후 코드 수정도 같은 권한으로 실행합니다. 접근 범위가 늘어나면 다시 검토해야 합니다.

브라우저 DEMO만 보려면 실행하십시오.

```sh
pnpm nx run git-logs:preview
# 소스 수정과 hot reload
pnpm dev
```

브라우저 DEMO는 **DEMO** 표시와 샘플 데이터를 사용하고 Git 명령은 실행하지 않습니다. 영문 샘플은 `http://127.0.0.1:4173/?lang=en&sample=en`에서 볼 수 있습니다.

브라우저 테스트는 Google Chrome을 사용합니다. Chromium을 사용하려면 `pnpm exec playwright install chromium`을 실행한 뒤 `PW_CHANNEL=chromium`을 설정하십시오.

## git-tools에서 이름 변경

플러그인 ID, 패키지 경로, Nx 명령은 이제 `git-logs`를 사용합니다. 로컬 설치 ID는 `local.git-logs`이고 tienne 소유 저장소에서 설치하면 `tienne.git-logs`가 됩니다.

기존 `.orca/git-tools/*.orcadiff` 문서는 계속 열 수 있습니다. `refs/git-tools/backups/`의 백업 ref도 그대로 남겨 둡니다. 새 문서와 백업에는 `git-logs`를 사용하고 자동으로 옮기지는 않습니다. Orca는 새 ID를 별도 플러그인으로 인식해 승인을 요구합니다. 새 플러그인이 준비되면 이전 `local.git-tools` 개발 연결을 해제해 패널과 편집기가 중복 등록되지 않게 하십시오.
